# Сравнение размеров shadow-сделок

Следующий независимый сеанс использует пять размеров. Контроль составляет 0,005 SOL. Сценарии на 5, 10, 20 и 30 USD переводятся в lamports с округлением вниз по одному снимку SOL/USD. Manifest содержит значение курса, источник, время последней сделки на бирже и время получения ответа. При недоступном или устаревшем курсе подготовка завершается ошибкой. USD PnL в итоговой таблице пересчитывается по этому же зафиксированному курсу. [Coinbase Exchange ticker](https://docs.cdp.coinbase.com/api-reference/exchange-api/rest-api/products/get-product-ticker)

## Запуск следующего исследования

```powershell
New-Item -ItemType Directory -Force work/next-copy/five-sizes
node scripts/next-copy-size-study.mjs prepare work/next-copy/five-sizes/study.json <wallet1> <wallet2>
node scripts/next-copy-size-study.mjs run work/next-copy/five-sizes/study.json <private-rpc-file>
node scripts/next-copy-size-compare.mjs work/next-copy/five-sizes/study.json work/next-copy/five-sizes/comparison
```

Локальный файл RPC содержит объекты `{http, ws}` с ключами `control`, `usd5`, `usd10`, `usd20`, `usd30`. Для пяти одновременных read-only процессов требуются выделенные квоты HTTP и достаточная квота WS. Разные URL с общей квотой не дают независимого бюджета. На каждый процесс приходится до 45 аккаунтных и 18 проверочных вызовов в минуту. При типичных 7–8 аккаунтных вызовах на котировку пять размеров для одного BUY и четырёх выходов могут потребовать 175–200 вызовов. Пиковые лимиты и лимиты по адресам дополнительно ограничивают покрытие. Если выделенных квот нет, используй одиночный процесс с `--size-sol` для диагностики и считай перекрытие недостаточным для сравнения.

Каждый процесс получает уведомления для тех же адресов, рассчитывает собственную BUY-котировку и четыре SELL-котировки на своё точное модельное количество. Матчинг требует одну входную сигнатуру и слот, одинаковый горизонт, для выхода по трейдеру ту же выходную сигнатуру и слот, а также совпадающие типы рынка. Допустимый разброс времени начала и завершения соответствующих RPC-котировок — 750 мс, а диапазона confirmed market context — 6 слотов. Если хотя бы один размер не прошёл условия, наблюдение учитывается в независимой статистике доступного размера и исключается из сравнения пяти размеров.

## Модель результата

SDK-цены включают комиссии Pump/PumpSwap и эффект размера сделки на резервы. Количество для SELL берётся из собственного BUY с допуском 100 bps и ограничением цены относительно трейдера. Из SELL quote удерживается 100 bps. Модель списывает по 0,00011 SOL на BUY, SELL и CLOSE, включая base fee, предполагаемые priority fee и tip. В основном net rent считается возвращённым. Отдельный сценарий списывает rent, записанный при BUY. [Комиссии Solana](https://solana.com/docs/core/fees)

Безубыточный SELL minOut равен размеру входа плюс 0,00033 SOL. До SELL haircut требуется не меньше `ceil((input + fees + rentLoss) / 0.99)` lamports по SDK после торговой комиссии. Это порог на модельное количество после BUY haircut.

Отчёт по каждому адресу, размеру и выходу содержит независимые и сопоставимые пары, win rate, net SOL/USD, ROI по закрытым позициям, результат без лучшей сделки, просадку по последовательности закрытий и rent-сценарий. JSON отдельно содержит p95 BUY/SELL latency, price impact и entry drift, минимум доступного SOL-резерва и причины отказа. Доля пропусков рассчитана среди BUY-сигнатур, замеченных хотя бы одним из пяти процессов. Пропуск, общий для всех процессов, требует независимого backfill.

Котировка описывает доступный снимок рынка. Проскальзывание сверх minOut, изменение резервов между чтением и исполнением и невозможность закрыть позицию остаются рисками. При отсутствии проверенной полноты истории и достаточного числа сопоставимых пар оценка остаётся **UNPROVEN**.
